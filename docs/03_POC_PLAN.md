# POC 計画 v1.0

> 本実装（M1〜）に入る前に、以下3つの POC で技術リスクを潰す。
> **POC ごとに結果レポート（結論・計測値・スクリーンショット・判断提案）をオーナーに提出し、GO/NO-GO 判断を仰ぐこと。**
> POC コードは捨てる前提の書き方でよいが、リポジトリの `poc/` 配下に残すこと。

## POC-1：iPad Safari での Three.js 描画性能

**目的**：ターゲット端末で本作規模のシーンが動くかの最重要検証。

**作るもの**
- 発掘サイト想定のダミーシーン：地形＋ボクセルグリッド（8×8×6 InstancedMesh）＋ローポリ恐竜1体（アニメ再生）＋ライト・シャドウ
- 画面上に FPS カウンター表示

**計測・合格基準**
- iPad Safari で 60fps → 文句なし合格／45fps 以上 → 合格（シャドウ設定を注意）／30fps 未満 → Babylon.js 比較検証へ
- 初回ロード時間、メモリ警告の有無も記録

## POC-2：「掘る」操作の気持ちよさ

**目的**：コアメカニクスの手触り検証。ここが楽しくないと企画が成立しない。

**作るもの**
- ボクセルグリッドをタップ／スワイプで削るプロトタイプ（ピッケル／ブラシ切替ボタン付き）
- 削った時の破片パーティクル＋SE（仮素材可）
- グリッド内にダミー化石（箱でよい）を埋め、damage カウント→★判定まで

**確認・合格基準**
- タッチ判定の精度：狙ったセルが削れるか（誤タップ率が体感で気にならないレベル）
- スワイプ連続削りが暴発しないか（化石を誤って傷つけすぎないか）
- 「化石が近いヒント」（音・エフェクト）でブラシに持ち替える導線が機能するか
- **オーナー家族による実機試遊の感想**を最終判断材料とする

---

## POC-3：恐竜アセットの現実性

**目的**：無料素材で「復元」体験が成立するかの確認。

**作るもの・調べること**
1. Quaternius／Kenney 等から恐竜 glb を 2〜3 体取得し、Draco 圧縮→ロード→アニメ再生
2. **骨格モデルの調達可否を調査**（CC0/CC-BY で使える skeleton 素材があるか）
3. 無い場合の代替案を試作：
   - 案 a：プリミティブ合成の記号的な骨（子ども向け絵本調に割り切る）
   - 案 b：生体モデルを白色・emissive で「ホネ風」表示
4. 骨パーツ分解（named mesh 単位で表示制御）が glb で成立するか確認

**合格基準**
- 12種ぶんの生体モデルの目処が立つ（同一素材集で統一感が出ること）
- 骨格表現の方針が決まる（既製／案a／案b のいずれかでオーナー承認）
- 恐竜1体あたりのファイルサイズ 2MB 以下（Draco 後）

## 進め方

1. POC-1 → 2 → 3 の順で実施（1 が NO-GO なら以降は保留してライブラリ再選定）
2. 各 POC は GitHub Pages のプレビュー URL（または dev ビルド）で**実機 iPad から触れる状態**にして報告すること
3. 3つ完了後、結果を反映して 02_TECH_SPEC を v1.1 に更新 → M1 開始の GO を得る

## POC-4：縦切りスライス「探す→掘る→集まる」

**目的**：GAME_DESIGN v2.0 の核である二層構造（フィールドで探す×発掘で掘り出す）が
1本の遊びとして成立するかの検証。「やってみないと分からない」部分を最小構成で通しにする。

**作るもの**
- すなの谷（1エリアのみ・徒歩30秒規模）：タップ移動＋追従カメラ（2本指回転・ピンチ）
- 固定配置の発掘ポイント3か所（露出した骨／地表のひび／崖下のがれき）。近づくと「！」→調べると発見→掘れる
- 発掘は POC-2 v2 のミニゲームを流用（1か所＝1個体＝骨2個の固定レイアウト）。**掘りかけの現場は残る**
- ベースキャンプ（テント＝げんき回復、はかせ＝ヒントのセリフ）
- 骨が集まるHUD。1種ぶんそろったら「ぜんぶそろった！」演出（復元は本実装で）

**確認・合格基準**
- タップ移動が6歳に通じるか（誤タップ・迷子・3D酔いがないか）
- 「！」→発見→掘るの導線が説明なしで通じるか
- フィールドシーンで 45fps 以上（iPad 実機）
- 家族試遊で「つぎのホネを さがしたい」という反応が出るか（企画の成立判定）

**この後**：POC-4 の結果を反映して 02_TECH_SPEC を v2.0 に改訂 → M1 開始の GO を得る

## POC-5：発掘コア再設計「掘る×みがく」（2026-08-19 追加）

**目的**：POC-4 試遊で判明した「手順執行の退屈さ」を解消する新発掘コアの手触り検証。
決定事項ログ「発掘コアの再設計」参照。

**作るもの**
- ピッケル＝土を掘る（制限なし）／ブラシ＝露出した骨をみがく（土は掘れない）。スタミナなし
- 骨は掘ると自動で「よごれた状態」で顔を出す。骨の形（せぼね＝長い／頭骨＝かたまり）から続きを推理して掘る。骨にピッケルが当たるとヒビ（★減）
- ブラシ2方式をページ内で切替比較：**こすり型**（指でこすって砂をはらう）／**ゲージ型**（タイミングで止める）

**確認・合格基準**
- 「みがいて骨が現れる」瞬間が気持ちいいか（こすり／ゲージどちらが良いか、家族の反応で決定）
- ✨の指示なしでも「骨が出たらブラシ」が自然に伝わるか
- 骨の続きを推理する緊張が生まれているか（うっかりヒビが「自分のせい」と感じられるか）
